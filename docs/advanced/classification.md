# 資料分級 <span class="badge-py">Python 版</span>

公司裡同時有雲端模型和地端模型時，機密的資料（例如人事、客戶資料）只能
交給地端模型處理。資料分級讓管理者替**資料來源**（知識庫、工具組、個人
知識庫）標上等級，並指定每個**模型**最高能處理哪一級。對話碰到超過目前
模型等級的資料時：

- **自動改用可以處理的模型**（例如地端的 Gemma），對話裡顯示提示，說明
  用到哪一級的資料、改由哪個模型回覆。
- **沒有可以處理的模型就停下來**，資料不會送給不能處理它的模型，並告訴
  使用者請管理者設定。

## 怎麼運作

1. 這一輪開始時，用使用者選的模型（例如雲端模型）。它只看得到使用者的
   問題，還沒有碰到機密資料。
2. agent 用 `search_knowledge` 搜尋到有分級的知識庫（有結果時），或執行
   了有分級的工具組裡的工具，就記下「這段對話碰過這個等級的資料」。
3. **每次呼叫模型前**都檢查：目前的模型能處理這個等級嗎？不行就改用
   `routeTo` 指定的模型；沒有指定時，依序從模型選單裡挑第一個可以處理的。
   包括 subagent 與壓縮對話時的模型呼叫。
4. **等級只升不降。** 資料已經在對話紀錄裡，之後每一輪（重新整理、重啟
   伺服器之後也一樣）都繼續用可以處理它的模型。記錄存在對話的
   `.meta.json`。

回覆下方顯示的模型名稱是實際回覆的模型；經過[模型中台](/guide/web#模型中台)時，
用量也記在實際呼叫的模型上。

## 設定

寫在 `harness.yaml`（網頁版可以在「管理平台 → 資料分級」設定，不必手改）：

```yaml
dataClassification:
  levels:                      # 由低到高；省略時是 公開、內部、機密
    - {id: public, name: 公開}
    - {id: internal, name: 內部}
    - {id: confidential, name: 機密}
  defaultClearance: internal   # 沒列在 models 的模型最高能處理到哪一級
  models:
    gemma-4-31b: confidential  # 地端模型可以處理機密資料
  routeTo: gemma-4-31b         # 超過時自動改用的模型
  personalKnowledge: internal  # 所有個人知識庫的等級（選填）
  toolsets:                    # 工具組的等級（選填）
    hr_system: confidential

knowledgeBases:
  hr:
    name: 人資規章
    classification: confidential   # 這個知識庫的等級
```

| 設定 | 說明 |
| --- | --- |
| `levels` | 等級，由低到高，至少兩個。`id` 寫在設定裡，`name` 顯示給使用者 |
| `defaultClearance` | 沒列在 `models` 的模型最高能處理的等級。省略時不限制（可以處理最高等級），**建議設定成雲端模型能處理的等級**，新加的模型才不會預設可以讀機密資料 |
| `models` | 每個模型最高能處理的等級，名稱和模型選單裡的一樣 |
| `routeTo` | 資料超過目前模型的等級時改用的模型 |
| `personalKnowledge` | 所有[個人知識庫](/guide/web#我的知識庫)的等級 |
| `toolsets` | 工具組的等級：這組工具執行成功後，就算碰過這個等級的資料 |
| `knowledgeBases.<id>.classification` | 知識庫的等級；沒寫的知識庫沒有分級 |

- 沒有 `dataClassification` 區塊時不使用資料分級，所有模型都能讀到所有
  資料；知識庫寫了 `classification` 卻沒有這個區塊會報錯。
- 等級只看搜尋**有結果**的知識庫：搜尋了機密知識庫但沒找到內容，不會
  改用模型。
- 網頁版在「管理平台 → 資料分級」取消啟用時，會一併拿掉每個知識庫的
  等級。設定的改動記在[稽核紀錄](/guide/web#稽核紀錄)。

## 網頁版

「管理平台 → 資料分級」（`/admin/classification`，只有管理者）：

- **等級**：改名稱、新增更高的等級或刪除（至少兩個）。
- **模型能處理的等級**：「其他模型」是 `defaultClearance`，表格列出模型
  選單裡的每個模型；「超過時自動改用」是 `routeTo`。
- **資料來源的等級**：每個知識庫、所有個人知識庫與每個工具組。

知識庫列表上會標出它的等級（例如「機密」）。對話用到分級資料時，輸入框
上方顯示提示。

API：

| 方法 | 路徑 | 說明 |
| --- | --- | --- |
| `GET` | `/api/admin/classification` | 目前的設定，另外附上畫面用的模型、工具組、知識庫清單 |
| `PUT` | `/api/admin/classification` | 儲存（格式同上；`enabled: false` 關閉） |

## 限制

- 分級是**對話層級**的：同一段對話碰過機密資料後，之後都用地端模型。
  想回到雲端模型，請開新對話。
- 使用者自己上傳到對話裡的檔案沒有分級；機密文件請放進有分級的知識庫。
- 第一輪呼叫（決定要不要搜尋）用的是使用者選的模型，它看得到使用者輸入
  的問題本身。問題裡有機密內容時，請讓使用者直接選地端模型，或用
  [群組](/guide/web#存取群組)限制能用的模型。
