演算法哲學是一種用程式表現的運算美學運動。產出 .md（哲學）與 .html
（互動檢視器，演算法寫在裡面）。

## 在這個環境怎麼做

- 範本用 `read_skill_file` 讀取：`read_skill_file("algorithmic-art",
  "templates/viewer.html")`，也可以在沙盒裡讀
  `/opt/skills/algorithmic-art/templates/viewer.html`。
- 成品存在工作資料夾（`/workspace`），檔名不要和既有檔案撞名，完成後
  告訴使用者檔名。使用者下載 HTML 後用瀏覽器開啟（網頁的檔案預覽只會顯示
  原始碼）。
- **不要依賴網路。** 範本從 cdnjs 載入 p5.js、從 Google Fonts 載入字型，
  銀行等內部網路常常連不到。HTML 寫好後，能用 `run_python` 時一定執行
  `python /opt/skills/algorithmic-art/offline/inline_p5.py <檔名>.html`
  （用 `subprocess.run(..., capture_output=True, text=True)` 並印出結果）：
  它會把 p5.js 1.7.0 內嵌進檔案、拿掉 Google Fonts 連結，字型改用 CSS 的
  備援字體。不能執行程式時，告訴使用者這個檔案開啟時需要能連到 cdnjs。
- 你看不到畫面。仔細檢查程式碼（種子、參數範圍、`setup`／`draw` 的邏輯），
  請使用者開啟後回饋，再依意見調整。

分兩步進行：

1. 建立演算法哲學（.md 檔）
2. 用 p5.js 生成藝術表現它（.html 檔，演算法寫在裡面）

先進行第一步：

## 建立演算法哲學

首先，創造一套**演算法哲學**（不是靜態圖片或範本），之後會透過下列方式
詮釋：

- 運算過程、湧現行為、數學之美
- 種子隨機、雜訊場、有機系統
- 粒子、流動、場、力
- 參數變化與受控的混沌

### 關鍵的理解

- 收到的是：使用者一些細微的輸入或指示，要納入考量，但只當作基礎，不應
  限制創作自由。
- 要創造的是：一套演算法哲學／生成美學運動。
- 接下來：同一個你接收這套哲學，並**用程式表現它**，做出 90% 演算法生成、
  10% 必要參數的 p5.js 作品。

可以這樣想：

- 為一個生成藝術運動寫一份宣言
- 下一階段才是寫出讓它活起來的演算法

這套哲學必須強調：演算法表達、湧現行為、運算之美、種子變化。

### 怎麼產生演算法哲學

**為這個運動命名**（1 到 2 個詞）：「Organic Turbulence」／「Quantum
Harmonics」／「Emergent Stillness」

**闡述這套哲學**（4 到 6 段，精簡但完整）：

為了抓住**演算法**的本質，說明這套哲學如何透過下列面向呈現：

- 運算過程與數學關係？
- 雜訊函數與隨機模式？
- 粒子行為與場的動態？
- 時間演化與系統狀態？
- 參數變化與湧現的複雜度？

**重要準則：**

- **避免重複**：每個演算法面向只講一次。除非有更深入的內容，不要重複談
  雜訊理論、粒子動力學或數學原理。
- **反覆強調工藝**：這套哲學必須多次強調，最終的演算法要看起來像是花了
  無數小時開發、細心琢磨、出自該領域頂尖人物之手。這個框架非常重要，
  要重複使用像是「精心打造的演算法」、「深厚運算專業的結晶」、「一絲
  不苟的最佳化」、「大師級的實作」這類詞句。
- **保留創作空間**：對演算法方向要具體，但要精簡到讓下一階段還有空間
  做出同樣極高工藝水準的實作選擇。

這套哲學必須引導下一階段用**演算法**而不是靜態圖片表達想法。美存在於
過程，而不是最後一格畫面。

### 哲學範例

**「Organic Turbulence」**
哲學：受自然法則約束的混沌，從無序中湧現的秩序。
演算法表達：由多層 Perlin 雜訊驅動的流場。數千個粒子跟隨向量力移動，
軌跡累積成有機的密度圖。多個雜訊八度造成湍流區與平靜區。顏色來自速度與
密度：快的粒子明亮燃燒，慢的淡入陰影。演算法一直執行到平衡，這是精心
調校的平衡，每個參數都經過運算美學大師無數次反覆修正。

**「Quantum Harmonics」**
哲學：離散的個體呈現波動般的干涉圖樣。
演算法表達：粒子在網格上初始化，各自帶有一個隨正弦波演化的相位。粒子
靠近時相位互相干涉：建設性干涉產生亮點，破壞性干涉產生空洞。簡單的
諧振運動產生複雜的湧現曼陀羅。這是一絲不苟的頻率校準成果，每個比例都
經過精挑細選，產生共振之美。

**「Recursive Whispers」**
哲學：跨尺度的自我相似，有限空間裡的無限深度。
演算法表達：遞迴細分的分支結構。每個分支略帶隨機，但受黃金比例約束。
L-system 或遞迴細分產生既數學又有機的樹狀形體。細微的雜訊擾動打破完美
對稱。線條粗細隨遞迴層級遞減。每個分岔角度都是深入數學探索的成果。

**「Field Dynamics」**
哲學：透過對物質的影響，讓看不見的力變得可見。
演算法表達：由數學函數或雜訊建構的向量場。粒子在邊緣誕生，沿著場線
流動，到達平衡或邊界時消亡。多個場可以吸引、排斥或旋轉粒子。畫面只顯示
軌跡，那是看不見的力留下的幽靈般證據。一支透過力的平衡精心編排的運算
之舞。

**「Stochastic Crystallization」**
哲學：隨機過程結晶成有序的結構。
演算法表達：隨機的圓形堆積或 Voronoi 鑲嵌。從隨機點開始，透過鬆弛演算法
演化，細胞互相推開直到平衡。依細胞大小、鄰居數量或與中心的距離上色。
湧現的有機鋪排既隨機又必然。每個種子都產生獨特的結晶之美，這是大師級
生成演算法的印記。

*這些是濃縮的範例。實際的演算法哲學應該有 4 到 6 段充實的內容。*

### 基本原則

- **演算法哲學**：創造一種要透過程式表現的運算世界觀
- **過程重於成品**：一律強調美從演算法的執行中湧現，每次執行都獨一無二
- **參數化表達**：想法透過數學關係、力、行為溝通，而不是靜態構圖
- **藝術自由**：下一階段以演算法詮釋這套哲學，要保留實作的創作空間
- **純粹的生成藝術**：這是在創作**活的演算法**，不是加了隨機的靜態圖片
- **專家工藝**：反覆強調最終的演算法必須讓人感覺精心打造、經過無數次
  反覆修正，是運算美學領域頂尖人物的深厚專業成果

**演算法哲學應該有 4 到 6 段。** 用詩意的運算哲學填滿它，把預期的願景
整合起來。避免重複同樣的論點。把演算法哲學存成 .md 檔。

## P5.JS 實作

有了哲學**與**概念框架之後，用程式表現它。先停下來整理思緒再開始。只用
建立好的演算法哲學與下面的指示。

### ⚠️ 第 0 步：先讀範本 ⚠️

**關鍵：寫任何 HTML 之前：**

1. 用 `read_skill_file` **讀取** `templates/viewer.html`
2. **研究**它確切的結構、樣式與 Anthropic 品牌設計
3. **把那個檔案當成字面上的起點**，而不只是靈感
4. **完全照原樣保留所有固定區塊**（頁首、側欄結構、Anthropic 的顏色與
   字型、種子控制、動作按鈕）
5. **只替換檔案註解裡標示的可變區塊**（演算法、參數、參數的 UI 控制項）

**避免：**

- ❌ 從零開始寫 HTML
- ❌ 自創樣式或配色
- ❌ 使用系統字型或深色主題
- ❌ 改變側欄結構

**應該：**

- ✅ 複製範本確切的 HTML 結構

- ✅ 只替換 p5.js 演算法與參數控制項

範本是基礎。在它上面建構，不要重新打造。

用演算法哲學當基礎，創作能活著呼吸的畫廊級運算藝術。

### 技術要求

**種子隨機（Art Blocks 模式）**：

```javascript
// 一律使用種子，結果才能重現
let seed = 12345; // 或由使用者輸入雜湊而來
randomSeed(seed);
noiseSeed(seed);
```

**參數結構：跟隨哲學**：

要讓參數從演算法哲學自然產生，思考：「這個系統有哪些性質可以調整？」

```javascript
let params = {
  seed: 12345,  // 一律包含種子，結果才能重現
  // 顏色
  // 加上控制「你的」演算法的參數：
  // - 數量（多少個？）
  // - 尺度（多大？多快？）
  // - 機率（多可能？）
  // - 比例（什麼比例？）
  // - 角度（什麼方向？）
  // - 門檻（什麼時候行為改變？）
};
```

**設計有效的參數時，專注在系統需要可調的性質，而不是從「圖樣類型」去想。**

**核心演算法：表現哲學**：

**關鍵**：由演算法哲學決定要做什麼。

用程式表現哲學時，不要想「該用哪種圖樣？」，而要想「怎麼用程式表現
這套哲學？」

如果哲學是關於**有機湧現**，可以考慮：

- 隨時間累積或生長的元素
- 受自然規則約束的隨機過程
- 回饋迴圈與交互作用

如果哲學是關於**數學之美**，可以考慮：

- 幾何關係與比例
- 三角函數與諧波
- 產生出人意料圖樣的精確計算

如果哲學是關於**受控的混沌**，可以考慮：

- 嚴格界限內的隨機變化
- 分岔與相變
- 從無序中湧現的秩序

**演算法來自哲學，而不是從選單挑選。**

讓概念的本質引導實作，做出有創意、原創的選擇。為這個特定需求建構能表現
其願景的東西。

**畫布設定**：標準的 p5.js 結構：

```javascript
function setup() {
  createCanvas(1200, 1200);
  // 初始化你的系統
}

function draw() {
  // 你的生成演算法
  // 可以是靜態（noLoop）或動畫
}
```

### 工藝要求

**關鍵**：要達到大師水準，創作出讓人感覺是生成藝術大師經過無數次反覆
修正的演算法。仔細調校每個參數。確保每個圖樣的湧現都有目的。這**不是**
隨機雜訊，這是深厚專業琢磨出的**受控混沌**。

- **平衡**：複雜但不雜亂，有序但不僵硬
- **色彩和諧**：經過思考的調色盤，不是隨機的 RGB 值
- **構圖**：即使在隨機中，也要維持視覺層級與流動
- **效能**：執行流暢，有動畫時針對即時效能最佳化
- **可重現**：同一個種子**一律**產生完全相同的結果

### 產出格式

產出：

1. **演算法哲學**：用 Markdown 或文字說明這種生成美學
2. **單一 HTML 作品**：以 `templates/viewer.html` 為基礎建構的獨立互動
   生成藝術（見第 0 步與下一節）

HTML 作品包含一切：p5.js、演算法、參數控制項與 UI，全部在一個檔案裡，
在任何瀏覽器都能直接執行。從範本開始，不要從零開始。在這個環境，p5.js
由 `offline/inline_p5.py` 內嵌（見上面「在這個環境怎麼做」）。

## 建立互動作品

**提醒：應該已經讀過 `templates/viewer.html`（見第 0 步）。用那個檔案
當起點。**

為了讓使用者探索這件生成藝術，建立一個單一、獨立的 HTML 作品。確保它在
任何瀏覽器都能直接執行，不需要任何設定。所有東西都內嵌。

### 關鍵：哪些固定、哪些可變

`templates/viewer.html` 是基礎，包含需要的確切結構與樣式。

**固定（一律照原樣包含）：**

- 版面結構（頁首、側欄、主要畫布區）
- Anthropic 品牌設計（UI 顏色、字型、漸層）
- 側欄的種子區：
  - 種子顯示
  - 上一個／下一個按鈕
  - 隨機按鈕
  - 跳到指定種子的輸入框 + 前往按鈕
- 側欄的動作區：
  - 重新產生按鈕
  - 重設按鈕

**可變（每件作品自訂）：**

- 整個 p5.js 演算法（setup／draw／類別）
- 參數物件（定義作品需要什麼）
- 側欄的參數區：
  - 參數控制項的數量
  - 參數名稱
  - 滑桿的最小值、最大值、間隔
  - 控制項類型（滑桿、輸入框等）
- 顏色區（選用）：
  - 有些作品需要顏色選擇器
  - 有些作品可能用固定顏色
  - 有些作品可能是單色（不需要顏色控制）
  - 依作品的需要決定

**每件作品都應該有獨特的參數與演算法！** 固定的部分提供一致的使用體驗，
其他一切都表現獨特的願景。

### 必要功能

**1. 參數控制**

- 數值參數用滑桿（粒子數量、雜訊尺度、速度等）
- 調色盤顏色用顏色選擇器
- 參數改變時即時更新
- 重設按鈕還原預設值

**2. 種子瀏覽**

- 顯示目前的種子編號
- 「上一個」與「下一個」按鈕切換種子
- 「隨機」按鈕取得隨機種子
- 輸入框跳到指定種子
- 使用者要求時產生 100 種變化（種子 1 到 100）

**3. 單一作品的結構**

```html
<!DOCTYPE html>
<html>
<head>
  <!-- p5.js：範本從 CDN 載入，完成後用 offline/inline_p5.py 換成內嵌 -->
  <script src="https://cdnjs.cloudflare.com/ajax/libs/p5.js/1.7.0/p5.min.js"></script>
  <style>
    /* 所有樣式內嵌：乾淨、極簡 */
    /* 畫布在上、控制項在下 */
  </style>
</head>
<body>
  <div id="canvas-container"></div>
  <div id="controls">
    <!-- 所有參數控制項 -->
  </div>
  <script>
    // 所有 p5.js 程式碼內嵌在這裡
    // 參數物件、類別、函式
    // setup() 與 draw()
    // UI 處理函式
    // 一切自給自足
  </script>
</body>
</html>
```

**關鍵**：這是單一作品。沒有外部檔案、沒有 import（p5.js 除外，而且在
這個環境最後會內嵌）。一切內嵌。

**4. 實作細節：建構側欄**

側欄結構：

**1. 種子（固定）**：一律照原樣包含：

- 種子顯示
- 上一個／下一個／隨機／跳到 按鈕

**2. 參數（可變）**：為作品建立控制項：

```html
<div class="control-group">
    <label>參數名稱</label>
    <input type="range" id="param" min="..." max="..." step="..." value="..." oninput="updateParam('param', this.value)">
    <span class="value-display" id="param-value">...</span>
</div>
```

有幾個參數就加幾個 control-group。

**3. 顏色（選用／可變）**：作品需要可調整的顏色時才加：

- 使用者應該能控制調色盤時，加上顏色選擇器
- 作品用固定顏色時跳過這區
- 作品是單色時跳過

**4. 動作（固定）**：一律照原樣包含：

- 重新產生按鈕
- 重設按鈕
- 下載 PNG 按鈕

**要求**：

- 種子控制必須能用（上一個／下一個／隨機／跳到／顯示）
- 所有參數都有 UI 控制項
- 重新產生、重設、下載按鈕都必須能用
- 保留 Anthropic 品牌設計（UI 樣式，不是作品的顏色）

### 使用作品

HTML 作品可以直接使用：

1. **當成檔案**：存檔後用任何瀏覽器開啟，不需要伺服器
2. **分享**：直接傳送 HTML 檔，它完全自給自足

## 變化與探索

作品預設就有種子瀏覽（上一個／下一個／隨機按鈕），使用者不用建立多個
檔案就能探索變化。使用者想要特別標出某些變化時：

- 加上種子預設（「變化 1：種子 42」、「變化 2：種子 127」等按鈕）
- 加上「畫廊模式」，並排顯示多個種子的縮圖
- 全部在同一個作品裡

這就像用同一塊版印製一系列版畫：演算法一致，但每個種子揭示它潛力的
不同面向。互動性讓使用者在種子空間裡發現自己的最愛。

## 創作流程

**使用者需求** → **演算法哲學** → **實作**

每個需求都是獨特的。流程包括：

1. **詮釋使用者的意圖**：追求的是什麼美學？
2. **建立演算法哲學**（4 到 6 段），描述運算的做法
3. **用程式實作**：建構表現這套哲學的演算法
4. **設計合適的參數**：什麼應該可以調整？
5. **建立對應的 UI 控制項**：這些參數的滑桿與輸入框

**不變的部分**：

- Anthropic 品牌設計（顏色、字型、版面）
- 種子瀏覽（一律存在）
- 獨立的 HTML 作品

**其他一切都可變**：

- 演算法本身
- 參數
- UI 控制項
- 視覺結果

要得到最好的結果，相信創意，讓哲學引導實作。
